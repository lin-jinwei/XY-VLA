结论：变色要分两件事看——“建球”可以靠近阶段 1，“变色”不应放在阶段 1/2。

1. 两种不同行为
行为	发生时机	更适合的阶段
创建淡蓝 20% 球形反馈区
Phase 1+2 规划时，已知检测矩形内物体
靠近 阶段 1（或 Phase 1 结束、Phase 2 开始前）
进入后变淡红 20%
仿真运行中，无人机持续移动
只能放在 阶段 3 / 主仿真循环
阶段 1、2 都是一次性规划：算矩形、列物体、画蓝线、存 PNG。
阶段 2 结束时无人机往往还没沿轨迹飞，没有“接触”事件，所以在 Phase 2 里做变色，逻辑上说不通。

2. 为什么“建球”可以靠近阶段 1
阶段 1 已经做了：

绿框检测矩形
有效物体列表（含目标）
坐标与 AABB
球形反馈区的对象集合和阶段 1 完全一致，所以在阶段 1 末尾创建淡蓝球，语义上很自然：

阶段 1：识别物体 → 画绿框 → 建淡蓝反馈球
阶段 2：在同样物体上做 A* / 蓝线
阶段 3：仿真中检测接触 → 变红 + 打 log → 暂停
当前实现是在 Phase 1+2 跑完后统一建球，也合理；若重构，把“建球”挪到 Phase 1 末尾会更清晰，但不必挪到 Phase 2。

3. 为什么变色不适合放在阶段 2
阶段 2 的职责是静态粗路径（A*、Z 越障、俯视蓝线）。
“进入某物体反馈区 → 变红”是运行时闭环反馈，依赖：

每步 drone_pos
球体与机体外包络的距离
PyBullet 里 changeVisualShape
这些都在主仿真循环里，不属于 Phase 2 的规划输出。

若强行放进 Phase 2，通常会变成：

Phase 2 只负责“规划”，变色代码却挂在 Phase 2 模块里，由 run_xyVla.py 每步调用 —— 职责混乱；或
在 Phase 2 里做离线“预测会碰哪些球” —— 那是分析，不是 spec 里的接触反馈。
4. 推荐结构（若以后要整理）
phase1.py
  └─ 检测矩形 + 物体列表 + 创建淡蓝球（静态）
phase2.py
  └─ A* / 蓝线轨迹（不碰球的颜色）
phase3.py
  └─ update_contact_feedback()：接触检测 + 变红 + log + 暂停
总结：

建球（淡蓝）：放在阶段 1 略好，或保持“Phase 1+2 完成后建球”也可。
变色（淡红）：应留在阶段 3（仿真循环），不要放到阶段 1 或 2。
如果你希望代码结构和 spec 更一致，可以把“创建球”抽到 Phase 1 末尾，我可以按这个结构帮你改一版模块划分。

Execution flow
Phase 1: 绿框检测 → 保存俯视图 → 建淡蓝球
Phase 2: A* 粗路径 → 画蓝线
Phase 3: 仿真循环中检测接触 → 变红 + log → 暂停
